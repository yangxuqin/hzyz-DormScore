# 业务规则（唯一权威说明）

> 本文档是 DormScore 业务规则的权威来源。代码实现位于 `worker/src/domain/dorm/`。
> 修改规则时必须同步本文档、`AGENTS.md` 与对应测试。

---

## 1. 每日总分

- 每日基础分 **20** 分，系统只扣分、无加分。
- `每日得分 = max(0, 20 - 每日总扣分)`；得分不为负。
- **原始 `totalDeduction` 完整保存/计算**，即使超过 20 也不截断（仅得分截断为 0）。

```
每日总扣分 = 床位扣分 + 公共区域扣分 + 纪律扣分
```

## 2. ★ 扣分池模型（核心）

### 2.1 定义

**「检查时段 × 检查位置」= 一个扣分池，固定扣 2 分。**

- 检查时段：`AM`（上午）、`PM`（下午），**完全独立计算**。
- 床位区域：`BED`（床面/床架）、`FLOOR`（床下地面）。

由此存在**且仅存在** 4 个床位扣分池：

| 池           | 含义     |
| ------------ | -------- |
| `AM + BED`   | 上午床面 |
| `AM + FLOOR` | 上午床下 |
| `PM + BED`   | 下午床面 |
| `PM + FLOOR` | 下午床下 |

- 每个池最多扣 **2 分**。
- 全天床位区域最大扣分 = 4 × 2 = **8 分**。

### 2.2 多床位命中只扣一个 2 分

这是 V2 相对 V1 最重要的修正。

> 上午：1 床床下出现问题，3 床床下出现问题。
> 业务结果：`AM + FLOOR = 2 分`，**不是** `1床 2 + 3床 2 = 4 分`。

命中的**床位数量只用于确定责任人员**，绝不参与扣分乘法。
代码中禁止 `bedChecks.length * 2` 之类的写法。

### 2.3 领域对象

```ts
interface BedPool {
  period: 'AM' | 'PM';
  item: 'BED' | 'FLOOR';
  beds: number[]; // 命中的床位 id，只决定责任人
  deduction: number; // 该池扣分快照（当前规则 2）
}
```

示例：

```json
{ "period": "AM", "item": "FLOOR", "beds": [1, 3], "deduction": 2 }
```

含义：「上午床下检查命中 1、3 床，此扣分池固定扣 2 分。」

### 2.4 历史快照

每个池保存 `deduction` 快照。未来若调整「每池 2 分」这一常量，历史记录**不重算**。

## 3. 个人分摊

对每个扣分池：

1. 取该池所有命中床位 `beds`；
2. 找出这些床位上的全部成员；
3. 排除当天请假（`LEAVE`）人员；
4. 剩余正常成员共同分担：`每人 = pool.deduction ÷ 正常责任人数`。

### 3.1 示例

宿舍床位-成员：1床 User1+User2；2床 User3+User4；3床 User5+User6；4床 User7。

`AM + FLOOR`，`beds = [1, 3]`，正常人员 User1/User2/User5/User6：

- 宿舍：**-2**
- 个人：User1 = 0.5，User2 = 0.5，User5 = 0.5，User6 = 0.5

### 3.2 有人请假

若 User2 请假，则由 User1、User5、User6 三人承担：`2 / 3 ≈ 0.67`，User2 为 0。

### 3.3 全部请假

若命中床位上的所有人都请假：

- 宿舍：**仍扣 -2**；
- 个人：**0**（无人承担）。

这是合法结果。**个人扣分总和不要求等于宿舍总扣分**；个人扣分允许小数，宿舍扣分为整数。

## 4. 公共区域

公共区域 6 项：垃圾桶、阳台地面、室内地面、厕所、洗衣槽/洗漱台、置物桌。
按「时段 × 项目」计，**每项 1 分**。

- 全部归**当天值日生**。
- 请假人员不能成为值日生（后端校验，返回 `DUTY_USER_ON_LEAVE`）。
- 计算引擎兜底：若值日生当天请假，公共区域不归任何人。

## 5. 纪律

- 纪律为**宿舍级别**。
- 讲话 **2 分/次**（上午次数 + 下午次数）。
- 讲话**不能计入任何个人扣分**。
- 展示页只展示真实存在的违纪日期与次数，不产生大量空白纪律记录。

## 6. 请假

- 请假只免除**个人责任**，不免除宿舍扣分。
- 请假人员不能担任当天值日生。
- 成员当天状态随记录保存（`daily_user_status`），保证历史回看时状态不失真。

## 7. 有效日与周期统计

- **有效日**：当天存在 `ACTIVE` 状态的每日记录；`REVOKED`（撤回）不参与任何统计。
- 周定义：**周一 ~ 周日**。
- 周得分率 = 本周有效日得分总和 ÷（20 × 本周有效天数）× 100%。
- 月得分率 = 本月有效日得分总和 ÷（20 × 本月有效天数）× 100%。
- 无有效日的周/月不产生数据点。

## 8. 卫生扣分频次

统计各检查项目的**发生次数**（不是扣分金额）：

- 一个床位扣分池按「一次」计入其区域项（`BED` 或 `FLOOR`）。
- 上午 + 下午同一项目都命中 → 计 2 次。
- 固定 8 项：床面、床下地面、垃圾桶、阳台地面、室内地面、厕所、洗衣槽、置物桌。

## 9. 记录状态

- 一天一条（`date` 唯一）。同一天重复提交 = 更新。
- **撤回**：不物理删除，状态置 `REVOKED`，不参与统计，可**恢复**。
- 修改：日期、值日生、成员状态、扣分项均可改；改日期若目标日期已有记录返回 `DATE_CONFLICT`。
- 所有写操作记录审计日志（前后快照 + 原因）。

## 10. 端到端示例

上午：`AM+BED` 命中 1、2 床，`AM+FLOOR` 命中 1、3 床；下午：`PM+BED` 命中 4 床；
公共区域上午 2 项、下午 1 项；讲话上午 1 次。

- 床位扣分 = 2 + 2 + 2 = 6
- 公共区域扣分 = 3
- 纪律扣分 = 2
- 总扣分 = 11，得分 = 20 - 11 = 9

个人（假设全员正常、值日生 User3）：

- `AM+BED`（beds 1,2 → User1/2/3/4）各 0.5
- `AM+FLOOR`（beds 1,3 → User1/2/5/6）各 0.5
- `PM+BED`（bed 4 → User7）2
- 公共区域：User3 +3
- 合计：User1 = 1、User2 = 1、User3 = 3.5、User4 = 0.5、User5 = 0.5、User6 = 0.5、User7 = 2
